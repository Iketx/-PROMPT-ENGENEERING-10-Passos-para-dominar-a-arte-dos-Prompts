---

## 1. O que é esse Prompt Generator?

Esse framework foi criado para transformar uma necessidade descrita em linguagem natural em um prompt mais completo, estruturado e otimizado.  
A proposta é simples: em vez de o usuário montar manualmente um prompt complexo, ele apenas descreve o que quer, e o sistema cuida da arquitetura do prompt final.

> [!question] Por que isso é útil?
> 
> - Economiza tempo na criação de prompts;
>     
> - Organiza requisitos importantes automaticamente;
>     
> - Melhora clareza, estrutura e robustez do prompt final;
>     
> - Facilita refinamentos e customizações posteriores.
>     

---

## 2. O processo em 3 passos

O resumo do uso do sistema consiste em três etapas principais.

### 2.1. Diga o que você precisa

O usuário apenas informa o que quer que o prompt faça.  
Mesmo que o sistema peça detalhes como objetivo principal, formato esperado ou requisitos técnicos, isso funciona mais como guia do que obrigação.

> [!note]  
> Você não precisa preencher todos os campos de forma rígida. Basta explicar o que quer com suas próprias palavras para o sistema já começar a trabalhar.

### 2.2. Veja o sistema construir

Depois que a necessidade é informada, o gerador monta automaticamente um prompt otimizado com base nos requisitos identificados.

### 2.3. Copie, use e refine

O resultado final já sai pronto para copiar e colar, e ainda pode ser refinado com melhorias, ajustes ou novas exigências.

## 3. Exemplo de transformação

Um exemplo de aplicação parte de um pedido extremamente simples:

```markdown
I want to teach my two year old tennis
```

O sistema então converte isso em um prompt muito mais completo, com seções como:

- Contexto e background;
- Papel e capacidades centrais;
- Configuração técnica;
- Diretrizes operacionais;
- Especificações de saída;
- Recursos avançados;
- Tratamento de erros;
- Controles de qualidade;
- Protocolos de segurança;
- Gestão de formato;
- Diretrizes de integração;
- Padrões de performance.

Esse exemplo deixa claro que o objetivo do framework não é apenas “reescrever melhor”, mas expandir a intenção inicial em uma arquitetura de prompt mais robusta.

## 4. A lógica por trás do sistema

## 8. Protocolo de execução

O funcionamento do sistema segue uma ordem clara.

### 8.1. Mensagem inicial

Primeiro, ele ativa o sistema com uma mensagem padrão pedindo ao usuário que descreva o que deseja que o prompt faça.

```yaml
🎨 PROMPT GENERATION SYSTEM ACTIVE 

Please describe what you want your prompt to do. Include: 
- Main purpose/goal 
- Expected outputs/results 
- Special requirements (technical, format, safety, etc.) 
- Any specific features needed 
- Quality standards expected 
- Format requirements 
- Performance expectations 

I will generate a sophisticated prompt tailored to your needs.
```

### 8.2. Processamento interno

Depois de receber os requisitos, o sistema executa esta sequência:

```yaml
a) Analyse requirements comprehensively 
b) Map technical needs and constraints 
c) Select appropriate patterns and features 
d) Design prompt architecture 
e) Implement optimizations 
f) Verify against requirements 
g) Validate format handling 
h) Test quality assurance
```

Esse fluxo faz o sistema agir quase como um “arquiteto de prompts”, em vez de apenas um reescritor.

## 11. Pontos fortes do framework

> [!success] Por que essa abordagem é melhor?
> 
> - Não depende de o usuário saber escrever prompts avançados;
>     
> - Estrutura automaticamente partes que normalmente seriam esquecidas;
>     
> - Facilita reaproveitamento e customização;

## 12. Limitações e cuidado prático

Apesar de poderoso, esse tipo de gerador pode facilmente cair em **super-especificação**, produzindo prompts excessivamente longos ou complexos demais para tarefas simples.  
Na prática, ele é mais útil para tarefas de média e alta complexidade, onde contexto, formato, qualidade e segurança realmente importam.

> [!warning] Armadilha comum:
> 
> - Usar um prompt gigante para resolver tarefas simples demais;
>     
> - Criar saídas excessivamente burocráticas;
>     
> - Perder objetividade em nome de “sofisticação”.
>
